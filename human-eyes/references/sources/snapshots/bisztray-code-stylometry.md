## Repository verification

- The paper-linked repository exists at https://github.com/LLMauthorbench/LLMauthorbench. Current `main` resolved to commit `6a1c2ac173c774cfbd012f4c81e8d0a51bb61eb7`; the latest commit present when arXiv v1 was submitted was `01d190a928f4e37c01fd171050f869ae6ed65525`.
- The dataset ZIP blob is identical at those commits. It contains 32,000 records, exactly 4,000 per recorded model, and 32,000 unique C-code byte strings with matching SHA-256 fields.
- The released dataset does not contain 4,000 unique prompt strings applied uniformly to all eight models. It contains 10,262 distinct prompt strings overall; each model has 2,000-2,385 distinct prompt strings; only 239 prompt strings occur for every model; 18,274 records belong to repeated model/prompt pairs. This directly qualifies the paper's “4,000 unique programming tasks” and “each task template is provided to each LLM” descriptions.
- The released five-class BERT, traditional-ML, and CodeT5 notebooks all use row-level label-stratified `train_test_split(..., test_size=0.2, random_state=42)` and do not group by prompt or task template. Because prompt strings repeat, the release does not establish task-disjoint validation.
- The repository supports the existence of the dataset, dataset-creation notebook, compile-check notebook, one BERT five-class notebook, one traditional-ML five-class notebook, and one CodeT5 five-class notebook. It does not include the binary-training notebooks or executable notebooks for every transformer baseline reported in the paper. The CodeT5 notebook uses `max_len=1024`, while the paper reports a 512-token CodeT5 result. The traditional-ML notebook uses code TF-IDF only and says extra features can be added; it does not reproduce the paper's claimed Joern/Table 4 feature extraction. Therefore the broad claim that all reported results are reproducible from the released scripts is only partly supported.
- The current repository adds `Independent_Validation.csv` after arXiv v1. It contains 100 labelled C-program rows: 54 have true label `gpt-4.1`, 46 have true label `gpt-4o`, and 51 prompt strings are distinct. Its `predicted` value matches `true_model` in 94 of 100 rows. The only columns are `true_model`, `predicted`, `prompt`, and `c_code`; there is no confidence column and no recorded generation/API provenance. This is a separate post-v1 aggregate repository artefact, not evidence that the paper's still-undisclosed native-API OOD set had 100 rows or 94% accuracy.
- The current repository also adds a later README acceptance citation after arXiv v1; it was inspected only to distinguish repository drift from the reviewed paper version.
