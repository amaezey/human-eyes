## Summary

The complete arXiv v1 paper studies closed-set attribution of LLM-generated C programs to their source model. It introduces a 32,000-record benchmark and an encoder-only CodeT5 classifier, reports 97.56% binary and 95.40% five-class validation accuracy, and finds that comments are a strong but non-exclusive cue. Full-text and repository review materially weakens the prior abstract-only record: the paper states only an 80/20 training/validation split, while the three preserved five-class BERT, traditional-ML, and CodeT5 notebooks reveal row-level stratification for their own workflows. No binary-training notebook is preserved, so binary split grouping is unstated; neither the paper nor the release establishes task-disjoint evaluation, and the paper reports no repeated-run uncertainty. The study is limited to C, known candidate models, and non-adversarial samples. Direct repository inspection also contradicts the paper's description of 4,000 unique tasks shared uniformly across all eight models and shows that the released scripts do not reproduce every reported experiment. The current repository's separate post-v1 validation CSV records 94 correct predictions across 100 labelled rows, but its missing generation/API provenance prevents equating it with the paper's still-undisclosed native-API OOD set. None of this is natural-language prose evidence, and none supports a human-eyes prose pattern, threshold, or authorship verdict.

## Main insights

- The study is source-model attribution among LLM-generated C programs, not human-versus-AI detection, human authorship attribution, prose-quality assessment, or natural-language stylometry.
- The released dataset contains 32,000 unique C-code byte strings and 4,000 records per model, but only 10,262 distinct prompt strings overall. Each model has 2,000-2,385 distinct prompt strings, only 239 prompt strings occur for every model, and 18,274 records belong to repeated model/prompt pairs.
- The paper reports only an 80/20 training/validation split. The preserved five-class notebooks `scripts/3_BERT_training-5-class_google_colab.ipynb`, `scripts/4_TRAIN_Machine_learning_google_colab.ipynb`, and `scripts/5_CodeT5-Authorship_5-class_google_colab.ipynb` implement row-level label-stratified splits without grouping by task template or prompt. No binary-training notebook is preserved, so the binary split's grouping and stratification are unstated. The reported validation scores do not establish task-disjoint generalisation.
- Exact duplicate code is removed; Type 1 and Type 2 clones, formatting differences, variable renaming, comments, and statement reordering are retained. Samples must survive `gcc -c`, and correct samples are randomly dropped to balance models. Results therefore apply to balanced, compilable, surviving C outputs rather than all model generations.
- CodeT5-Authorship uses the CodeT5+ 770M encoder, the first-token representation, two linear layers, GELU, and 20% dropout. The released five-class notebook uses a 1,024-token maximum although the paper reports the CodeT5 result at 512 tokens.
- In the binary task, CodeT5-Authorship reports 97.56% accuracy and 97.59% precision. In the five-class task, it reports 95.40% accuracy and 95.41% precision.
- The authors summarise Table 5 by saying comment removal moves most binary-validation curves by 2-3 percentage points, but only 5 of the 11 exact with/without-comment pairs fall in that band. They report median drops of 2.5 points for classical learners and 3.1 for transformer models. Direct calculation from the displayed pairs instead gives 2.9 points for the seven classical models and 2.405 points (about 2.4) for the four transformers, an internal arithmetic discrepancy; all 11 paired drops span 0.2-5.8 points. Five-class BERT accuracy falls from 92.65% to 85.45%. This is code-comment evidence within this benchmark, not evidence about prose comments or universal model fingerprints.
- The hand-engineered structural metrics in Table 4 reportedly move classical-model validation curves by no more than about 0.4 percentage points; comment tokens have a larger effect. The paper does not report a controlled feature-by-feature ablation table.
- DeepSeek-V3 is the most confused class: CodeT5-Authorship correctly labels 723 of 800 validation examples, with remaining errors distributed mainly to Llama-3.3-70B, Claude-3.5-Haiku, and GPT-4.1; reverse confusions also occur.
- The paper says it built an out-of-distribution native-OpenAI set from new prompts and templates, but does not disclose that set's size or aggregate results. It reports only two illustrative predictions: 99% confidence for one GPT-4o output and 100% for one GPT-4.1 output. Those two confidence outputs are not an accuracy estimate, calibration study, or adequate test of proxy artefacts.
- The current repository separately contains a post-v1 `Independent_Validation.csv` with 100 labelled GPT-4.1/GPT-4o C programs, a 54/46 true-label split, 51 distinct prompts, and 94 matching predictions. It has no confidence column or recorded generation/API provenance, so it is an aggregate validation artefact but cannot be identified as the paper's native-API OOD set.
- The authors explicitly limit the work to moderate-size classifiers, five known models in multi-class evaluation, C only, no deliberate obfuscation, no unseen-model/open-set attribution, no zero/few-shot large-decoder evaluation, and substantial GPU cost.
- The linked repository supports the existence of the dataset, five notebooks, and a later aggregate validation CSV but not full reproduction of all binary, transformer-baseline, Joern-feature, or paper-native-API results. Its CodeT5 token length and traditional-ML feature path differ from the paper's reported setup. The README also says Llama 3.1 where the paper, dataset, and notebooks use Llama 3.3, and lists 2,048-token BERT rows where the paper and released BERT notebook use 512.
- The strongest human-eyes use remains a domain-boundary lesson: “stylometry” evidence must not be moved from generated C code into natural-language prose rules without direct transfer evidence.
