# Decision register

Single decision point for every proposed product change arising from source evidence. One row per change. Nothing in the product layer (`human-eyes/scripts/`, generated `patterns.md`, `SKILL.md`, `process.md`, root `README.md`) changes without a row here carrying Mae's decision.

## How to read this file

- Every table has the same seven columns: **ID | Change | Evidence | Extends | Decision | Commit | Validation**.
- **Change** describes the proposal. Text labelled "original-pass note/disposition" is the importing agent's assessment, recorded for context; it is never a ruling.
- **Evidence** holds claim keys in `slug:CNN` form, matched by `dev/tools/reconcile_register.py` against the classification CSV.
- **Extends** points at an older row covering the same material. Deciding either row closes both, and the closing sweep must rule or re-queue every claim the linked row cites (orphan rule, Mae 2026-07-17). A closed-via-link row carries its own `via DR-NNN` stamp.
- **Decision** is exactly one of: `pending`, `approved <date>`, `rejected <date>`, `pos-dependent-pattern <date>` (reserved solely for patterns blocked on the POS tagger from Mae's other project). Detail follows in parentheses.
- **Commit / Validation** are filled at implementation; validation names the test or check holding the change in place.
- Sections group rows by origin only; the columns and statuses never vary by section.

Run `python3 dev/tools/reconcile_register.py` to see how many classification rows with an additive or evaluate component are not yet accounted for. The count must stay at zero.
