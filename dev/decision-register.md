# Decision register

Single decision point for every proposed product change arising from source evidence. One row per change. Nothing in the product layer (`human-eyes/scripts/`, generated `patterns.md`, `SKILL.md`, `process.md`, root `README.md`) changes without a row here carrying Mae's decision.

## How to read this file

- Every table has the same seven columns: **ID | Change | Evidence | Extends | Decision | Commit | Validation**.
- **Change** describes the proposal. Text labelled "original-pass note/disposition" is the importing agent's assessment, recorded for context; it is never a ruling.
- **Evidence** holds claim keys in `slug:CNN` form, matched by `dev/tools/reconcile_register.py` against the classification CSV.
- **Extends** points at an older row covering the same material. Deciding either row closes both, and the closing sweep must rule or re-queue every claim the linked row cites (orphan rule, Mae 2026-07-17). A closed-via-link row carries its own `via DR-NNN` stamp.
- **Decision** is exactly one of: `pending`, `approved <date>`, `rejected <date>`, `pos-dependent-pattern <date>` (reserved solely for patterns blocked on the POS tagger from Mae's other project). Detail follows in parentheses.
- **Commit / Validation** are filled at implementation; validation names the test or check holding the change in place.
- Sections group rows by origin only; the columns and statuses never vary by section.

Run `python3 dev/tools/reconcile_register.py` to see how many classification rows with an additive or evaluate component are not yet accounted for. The count must stay at zero.

## Screening rule and the 2026-07-25 re-screen

An `Original-pass note` or `Original-pass disposition` in a Change cell is the importing agent's opinion, written during ingestion. It is not a ruling and it is not a screening result. Many of those dispositions say "do not promote" because the source is a practitioner page, a vendor page, an unreplicated study, or a paper with no matched human control. **That reasoning is void under rule 1 of `dev/decision-walkthrough-approach.md`:** human-eyes audits prose habits AI overuses, it is not an authorship detector, and a practitioner phrase list is sufficient evidence for a watch-list addition. Never repeat an original-pass disposition to Mae as though the question were settled.

Every pending row was re-screened on 2026-07-25 against what its sources actually contain, ignoring the dispositions. Every pending row carries the result in its own Change cell, in a sentence beginning `Screened 2026-07-25:`. Each says one of four things: **addable** with the concrete mechanism and its detector type named; **nothing left to add** where the live checker already does what the row asks, so the row needs verifying against `grade.py` and closing; **documentation** where the work is a citation, label, or wording fix with no detector change either way; or **nothing addable** with the reason, which is always that no form appears in the text, never that the evidence is too weak. Re-screen a row only if its source card is re-ingested or a claim is added to it.
