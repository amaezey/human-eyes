# human-eyes

A [Claude Code skill](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/skills) for auditing and rewriting prose that carries common AI-writing tells.

human-eyes is a pattern detector, not an AI detector. It flags specific patterns in text that statistically give readers the "AI ick" when used without intent.

Inspired by [blader/humanizer](https://github.com/blader/humanizer), built around a deterministic grader, an iteration harness, and a corpus of matched human and AI essays for testing.

## Install

### Clone and symlink (preferred)

Get updates with `git pull`. Run from your local checkout.

```bash
git clone https://github.com/amaezey/human-eyes.git ~/.local/share/human-eyes
ln -s ~/.local/share/human-eyes/human-eyes ~/.claude/skills/human-eyes
```

```bash
npx skills@latest add amaezey/human-eyes/human-eyes
```

## Why this exists

Much of the text we consume and create today is generated by AI. While there are some obvious signs of AI writing, there are subtler tells that are harder to diagnose and repair. The effect is cumulative: AI fingerprints on the voice, rhythm, structure, and phrasing all compound.

The patterns aren't the problem. Good writers use triads, em dashes, and contrast framing on purpose. AI uses them without intent. human-eyes views AI writing as inferior to human writing but accepts the reality that it is here to stay. Rather than rewriting blind (like most AI writing skills), it checks your text against a catalogue of research-backed and house-style patterns and gives you options to act on each flag.

Surface patterns are detected by a deterministic Python script. Deeper problems, like structure and tone, are judged against a fixed list of questions, so the model cannot improvise, and the grader rejects answers that are missing or no longer match the text.


## What it does for you

When you invoke the skill and provide text, human-eyes runs a complete **Audit** first: a summary block plus every flagged pattern with exact evidence from the draft. Auto-detected patterns appear first, followed by agent-assessed findings.

The Audit ends with a prompt: full coverage report, suggestions, rewrite, or save. Each runs only when asked. Write is separate: it starts from a brief instead of an existing draft.

- **Full coverage report**: the same audit plus coverage tables for every check, both auto-detected and agent-assessed.
- **Suggestions**: alternative phrasing for each flag.
- **Rewrite**: rewrites the draft, checks facts and references, then audits the result again. It has two depth settings: Balanced fixes surface and strong patterns; All also reworks structural ones.
- **Write**: a fresh draft to a brief, with the patterns in mind.
- **Save report**: writes the audit or before/after comparison to Markdown.

## Usage

Invoke with `/human-eyes` or ask Claude to "audit this", "human-eyes this", "unsloppify", "strip the AI tells", or "rewrite to sound human".

### Run the grader directly (no LLM)

The grader can produce deterministic surface-only output without an LLM. A complete Audit also needs answers for every record in the semantic registry.

```bash
python3 human-eyes/scripts/grade.py preflight <file> --work-bundle /tmp/human-eyes-work.json
python3 human-eyes/scripts/grade.py audit <file> --work-bundle /tmp/human-eyes-work.json --format markdown
```

`preflight` writes a bound work bundle containing the semantic questions and candidate spans. Complete every semantic answer in that bundle before running `audit`. For deterministic development output, use `audit <file> --surface-only`; surface-only output cannot unlock Suggestions, Rewrite, or Write.

## How it works

human-eyes has four layers:

- **Pattern catalogue.** A registry of named AI-writing patterns with severity, sources, and before/after examples. Source of truth is `human-eyes/scripts/patterns.json`; the human-readable view is `human-eyes/references/patterns.md`.
- **Grader.** A deterministic Python script (`human-eyes/scripts/grade.py`) that runs regex and density checks against the draft. No LLM in this layer, so the same input always produces the same surface scan.
- **Agent-judgement registry.** Fixed semantic readings the grader cannot settle with regex alone, covering structure, reference, tone, stance, audience fit, genre, and internal consistency. The registry lives in `human-eyes/scripts/judgement.json`.
- **Bound work bundle.** `preflight` binds the source text, catalogue, document structure, candidate spans, and semantic questions with digests. The final Audit accepts the bundle only when every required answer is present and still matches the source.

Any generated suggestion or rewrite is checked in context and audited again against a fresh bundle.

## Patterns

Patterns are organised by category. Full before/after examples in `human-eyes/references/patterns.md`.

- **What it is**: a one-sentence plain-English description of the pattern.
- **Check**: how the pattern is detected.
    - `regex` runs against the text deterministically.
    - `agent` runs as a small LLM reading on the whole draft (items defined in `human-eyes/scripts/judgement.json`).
- **Severity**: enforcement tier. What a rewrite does with the flag.
    - `hard_fail` is always fixed.
    - `strong_warning` is fixed unless the user explicitly keeps it after disclosure.
    - `context_warning` is reviewed against context; the user decides what stays.
- **Source**: external attribution(s) for the pattern as a sign of AI writing, linked to the source card in `dev/references/sources/`.

## What testing showed

human-eyes ran across 63 human-written documents and 49 AI-written documents.

- AI documents drew 41% more flags overall than human documents.
- On the serious flags, AI drew 62% more.

Ten of the 66 signals separated the two groups most sharply. Ranked by the gap between them, not by how often they fire.

|---|---|---|---|

| Average word length | 13% | 65% | 52 |
| Paragraph length uniformity | 16% | 63% | 47 |

| Latin-root verbs | 14% | 49% | 35 |
| "It" as a subject | 17% | 47% | 30 |
| Participial clauses | 37% | 65% | 28 |

### Limits of the test set

- 47 of the 63 human documents are from the 21st century. The rest are 19th and 20th century literature and eight older legacy samples.
- 10 of the 49 AI documents are rewrites of human documents that also appear in the human set.
- Cut-offs come from published research on human and machine text. They were then checked against the same 112 documents the figures above measure, so the results are not from unseen writing.

## Where to be careful

- **Patterns drift.** AI vocabulary lists go stale ("delve" peaked in 2023 to 2024). The catalogue needs periodic refresh.
- **The skill itself is an LLM.** It can introduce the patterns it is trying to catch (flattening the author's stance, stripping out pronouns, swapping specific words for generic ones). The semantic-preservation step in the rewrite flow mitigates this but cannot eliminate it.
- **Detection is asymmetric.** The skill catches AI doing patterns badly. It can also wrongly flag humans doing the same patterns well. The audit voice tries to make this distinction visible; the user has to apply judgement.
- **Sample sizes are small.** The genre-matched corpus behind several calibrations is 5 documents per group. Treat the findings as directional.

## What's next

Active work, with open questions tracked in [`dev/hypotheses.md`](dev/hypotheses.md):

- Calibrating thresholds by register (literary essay vs corporate doc vs news copy).
- Demoting pattern checks that do not separate humans from AI in matched genres (em dashes and manufactured insight may belong in softer categories).
- Growing the matched corpus past n=5 per group, with bootstrap confidence intervals so weak-signal patterns demote automatically.
- Calibrating severities on the agent-judgement items against the corpus rather than curated guesses.
